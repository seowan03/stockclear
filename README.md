# 📦 StockClear

> **기업의 숨은 자금을 찾아주는 스마트한 재고 파트너**

**StockClear**는 기업의 재고 데이터를 분석하여 장기재고 및 악성재고를 식별하고,
재고 위험도를 시각화하여 **효율적인 재고 처분 전략을 추천하는 재고 관리 플랫폼**입니다.

---

## 팀구성
- 팀장: 임서환 
- 팀원: 김태호
- 팀원: 이병우
- 팀원: 박지훈
- 팀원: 양상명


## 📌 프로젝트 소개

기업에서는 판매가 지연되는 재고가 장기간 보관되면서

- 보관 비용 증가
- 자금 회수 지연
- 상품 가치 하락
- 재고 관리 비효율

등의 문제가 발생할 수 있습니다.

StockClear는 사용자가 보유한 **Excel/CSV 재고 데이터를 업로드**하면
데이터를 기반으로 재고 상태를 분석하고 위험도를 분류합니다.

또한 LLM을 활용하여 분석 결과를 바탕으로 상품별 **재고 처분 전략**을 제공합니다.

---

## 🎯 프로젝트 목표

1. Excel/CSV 형태의 재고 데이터를 간편하게 업로드
2. Pandas를 활용한 재고 데이터 분석
3. 상품별 재고 위험도 자동 분류
4. 분석 결과를 대시보드에서 직관적으로 제공
5. LLM을 활용한 상품별 처분 전략 추천
6. 재고 보관 비용 및 자금 회수 지연 문제 개선

## 일별 판매량 보관

현재 업로드에서 만드는 일별 판매량은 **실제 주문 기록이 아닌 더미 데이터**이며 생성 종료일은 2026-09-30입니다. 최근 약 1년은 `inventory_daily_metrics`에 일별로 두고, 그보다 오래된 **완료된 월**은 품목별 합계로 `inventory_monthly_sales`에 보관합니다. 과거 일별 값을 월별 합계로 나누어 다시 조회할 수는 없습니다.

기존 DB는 앱 시작 시 월별 테이블과 일별 날짜 인덱스를 생성합니다. 기존 일별 행은 이 단계에서 삭제되지 않습니다. 전환 전 DB를 백업한 뒤, 예약 작업에서 아래 명령을 **매일 한 번** 실행하세요. 기준일은 기본적으로 한국시간(UTC+9) 오늘이며, `--as-of`는 테스트용 기준일을 고정할 때 사용합니다.

```powershell
python -m app.services.daily_inventory_service --batch-size 100
```

각 배치는 월별 합계 저장과 오래된 일별 행 삭제를 하나의 트랜잭션으로 처리합니다. 중단 후 재실행해도 합계가 중복 누적되지 않습니다. 명령은 JSON으로 처리 건수·남은 오래된 일별 행 수·전체 일별/월별 행 수·실행 시간을 출력하며, 실패 시 오류 종류와 실패 배치 수를 stderr에 출력합니다. 예약 작업에서 실패 시 경고를 설정하세요. 월별 합계는 DB 보관용이며 재고 목록에 월별 조회 기능을 추가하지 않습니다. 기존 일별 API는 보관된 날짜에 빈 결과를 반환합니다. 실제 판매 이력을 수집하려면 더미 생성 로직과 별도의 판매 입력 경로가 필요합니다.

2026-10-01 기준 격리 SQLite에서 100품목(2025-01-01 입고, 2026-09-30까지 생성)을 시험했을 때 일별 63,700행 중 27,200행을 월별 900행으로 전환해 일별 36,500행이 남았습니다. 이 로컬 환경에서는 생성 5.71초, 전환 0.93초였으며 운영 MySQL의 성능을 뜻하지 않습니다. 운영 DB는 백업 후 소량부터 전환하고 행 수·실행 시간을 별도 측정해야 합니다.
